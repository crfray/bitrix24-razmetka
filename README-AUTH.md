# Просмотр и авторизация редакторов

Без входа доступны таблица, поиск, фильтры, карточки и медиа. Изменение событий,
звёздочек, удаление и загрузки требуют входа. При попытке редактирования появляется
форма входа; после успешного входа можно изменить данные. Все учётные записи имеют
права редактора общих данных. Саморегистрации и предустановленного пароля нет.

## Создание редактора

Из каталога приложения, от пользователя сервиса:

```sh
python3 auth.py set-password editor
```

Пароль вводится скрыто дважды, минимум 12 символов. Та же команда меняет пароль
и отзывает все прежние сессии. Отключение и список учётных записей:

```sh
python3 auth.py disable editor
python3 auth.py list
```

Пароли хранятся как PBKDF2-HMAC-SHA256 (600000 итераций, индивидуальная случайная
соль). В SQLite лежат хеши случайных токенов сессий. Сессия действует 8 часов;
выход, смена пароля и отключение редактора отзывают доступ. Попытки входа ограничены:
10 на логин и 60 на IP за 15 минут; успешный вход сбрасывает счётчик логина.
IP берётся из TCP-соединения, недоверенные forwarded-заголовки игнорируются.
За reverse proxy IP-лимит общий для его соединений: дополнительно настраивать
лимит входов по реальному клиентскому IP на доверенном proxy.

## Конфигурация

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `RAZMETKA_AUTH_DB` | `.auth/users.sqlite3` рядом с кодом | Постоянная SQLite для редакторов и сессий |
| `AUTH_COOKIE_SECURE` | `1` | Secure cookie для HTTPS; `0` только для локального HTTP |
| `AUTH_ORIGIN` | HTTPS + Host запроса, либо HTTP при Secure=0 | Точный origin браузера, например `https://projects.example.com`, без пути |
| `HOST` | `127.0.0.1` | Для Docker bridge задать `0.0.0.0`, backend-порты наружу не публиковать |

На VPS задать `RAZMETKA_AUTH_DB` в постоянном каталоге, доступном пользователю
сервиса; такую же переменную использовать при вызове auth.py. Два процесса могут
использовать одну SQLite и общий список редакторов. Cookie и сессии разделены по
пространствам project/tasks, вход в каждое выполняется отдельно. Для systemd добавить
Environment в соответствующий unit или drop-in, затем daemon-reload/restart.

Для HTTPS Secure-cookie включена по умолчанию. Reverse proxy должен передавать
правильный Host, либо явно задать AUTH_ORIGIN отдельно для каждого сервиса.
Значение Origin проверяется на каждом POST, кроме анонимного отказа в записи;
изменения также требуют сессионный X-CSRF-Token. Тела запросов ограничены до
чтения в память: JSON 1 MiB, base64-картинка 9 MiB, raw-медиа 80 MiB.

Локальный запуск без TLS:

```sh
AUTH_COOKIE_SECURE=0 python3 server.py project
AUTH_COOKIE_SECURE=0 python3 server.py tasks
```

SQLite, её WAL/SHM и data-* сохранять отдельно от образа. Учётные данные и сессии
не добавлять в Git и не отдавать reverse proxy как статические файлы. Для живой
SQLite резервную копию делать SQLite backup API или при остановленных процессах;
не копировать только основной файл при активном WAL.

Случайный URL настраивается отдельно на reverse proxy: приложение всё ещё использует
абсолютные /api и /media. Секретный префикс только для HTML не скрывает API/медиа.
Все опубликованные данные доступны без входа по выбранной модели; этот URL не является
границей доступа на запись. CPU, RAM и сеть можно наблюдать на уровне VPS;
изменения мониторинга не входят в эту доработку приложения.

## Проверки

```sh
python3 verify_auth.py
python3 verify_areas.py
node --check app/auth.js
```

Проверки запускают локальные серверы с искусственными данными во временных папках.
MANIFEST.json относится к исходному архиву: после этой доработки его старые хеши
изменённых файлов ожидаемо не совпадают. Сам манифест сохранён как сведения о поставке.
